Koden Brain — the Librarian

How the brain lives inside Koden. One quiet helper that keeps your library fresh so your AI terminals are always effective. · draft for alignment

You pick one folder where all your projects live — your Library. Inside Koden lives a Librarian: a quiet helper that runs whenever the app is open and keeps that library tidy, so any AI you open in a terminal already understands your work.

You never have to manage it. It doesn't nag, and it never runs when Koden is closed.

What you actually experience

📂 Pick your workspace, once
On first launch you choose the folder that holds your projects. That's the single source of truth — work, personal, hobby, anything.
⚡ It catches up when you open Koden
The Librarian notices what changed since last time (even if you edited elsewhere) and quietly updates itself in a few seconds.
🧠 Your AI starts already knowing the project
Open a Claude or Codex terminal and it's handed a short briefing about your code automatically — so it doesn't waste time (and tokens) re-reading everything.
↩️ Pick up where you left off
It remembers the last few things you were doing in each project. Crash, power cut, or just close the app — reopen and it knows where you were.
🔄 It re-learns your code as it changes
Make real changes and it quietly re-indexes so search and the AI stay accurate. Tiny edits it ignores — not worth the effort.
🔎 Ask in plain language (optional)
"Where's the checkout code?" works — but mostly the Librarian just works behind the scenes for the AI, not for you.

Free to start, smarter with a key. Out of the box the Librarian does keyword search, keeps your code fresh, and handles resume — no account, no cost. Add an OpenAI key and it unlocks meaning-based search ("find the login thing" even if you don't know the function name) and tidies your project memory — using a cheap model, only when it's worth it, with the running cost always visible to you.

One Rust module — src-tauri/src/modules/brain/ — and one in-process worker thread (app-lifetime; started from .setup(), fail-open). It is a "daemon" only in the loose sense: it lives inside Koden, runs while the window is open, and is gone when you close it. No OS service, no tray. Conductr's proven brain, reimplemented native in Rust.

2The cost tiers — why the Librarian is smart, not linear

Work is split by cost. The cheap stuff always runs; the key + the judgment are spent only where they matter. It decides on its own and never prompts you.

Re-indexing is so cheap that gating it behind an LLM would cost more than doing it — so the model's judgment is spent on significance, not on "should I run a free op." That's the whole reason the Librarian has a key.

4The two payoffs — what the brain feeds back out

📨 Gist injection (for the agents)
At agent launch the Librarian builds a token-bounded, fingerprint-stable gist (cache-safe: unchanged code → byte-identical file) from the same query path as search, and injects it through the existing --append-system-prompt channel. Vendor-agnostic — works for Claude, Codex, Gemini, GLM.
↩️ Resume (for you)
A rolling "last N things" per project (à la Mem0/Supermemory) + per-pane lifecycle, journaled to SQLite. On boot → recovery cards: "you were adding Stripe checkout to the candle shop." Open question: capture your prompts vs a 1-line summary.

5Borrowed from Conductr → reimplemented native

tokenizer identifier-aware (camelCase/stem) BM25 K1=1.2 / B=0.75 RRF fusion (+ real per-leg weights) AST graph tree-sitter — upgrade over Conductr's regex semantic embeddings + hybrid temporal memory + changed-since propose-not-apply memory (human-gated)

6The key — own, decoupled, budgeted

The Librarian's OpenAI key (embeddings + a cheap chat model) is separate from whatever the terminals run, and powers only Tier 1 + 2. Fully autonomous (no approval prompts) — so the guardrail is a visible running spend + a hard cap: "12¢ today · 2 significance calls · stops at your ceiling." Autonomy behind a glass wall, not a black box. Default-off until a key is added.
